Trilha Prática — AI Engineering Workbench

Construindo, do zero ao PR validado, os exemplos técnicos inspirados na palestra sobre Codex, agentes, loops, harness, skills e maximização de valor.

Objetivo

Construir um AI Engineering Workbench: uma mini-plataforma local com chat, agente com ferramentas, loop de validação, correção automática, UI colaborativa, diff viewer, subagentes de review, telemetria e documentação de PR.

Validação

Conteúdo checado contra 18 fontes primárias/oficiais e auditado por script local.

0

Montar o laboratório de engenharia com agentes

~35 min 2 nervo(s)

Resultado prático: Criar o monorepo ai-engineering-workbench com AGENTS.md, apps, packages, workflows e estrutura para exemplos práticos.

Por que existe: A palestra não é sobre copiar uma demonstração isolada. Ela descreve uma forma de engenharia em que o agente precisa de ambiente, instruções versionadas, ferramentas, validação e pontos de inspeção. O laboratório cria esse chão técnico.

Tarefas práticas

  • Criar o monorepo ai-engineering-workbench.
  • Adicionar apps/agent-api, apps/workbench-ui, packages/tools, packages/validation, packages/skills e packages/evals.
  • Criar um AGENTS.md com comandos obrigatórios, padrões de diff e critérios de parada.
  • Criar scripts npm para lint, test, build e validate.

1

Criar o loop mínimo com tools e function calling

~55 min 2 nervo(s)

Resultado prático: Implementar um backend que recebe uma meta, deixa o modelo escolher ferramentas locais e continua até produzir uma resposta final.

Por que existe: O primeiro salto prático é sair de chat passivo para um agente que age. Na palestra, isso aparece quando o agente passa a fazer tarefas de computador e não apenas sugerir código.

Tarefas práticas

  • Criar tools read_file, write_file, search_project e run_tests.
  • Expor POST /agent/run.
  • Converter tool calls em execução local controlada.
  • Registrar steps em JSON para inspeção posterior.

Entregáveis

apps/agent-apipackages/toolsPOST /agent/runtrace JSON de execução

Contrato da primeira execução

POST /agent/run

{
  "goal": "Crie uma função sum(a,b), teste e explique a mudança"
}

Resposta esperada:
{
  "status": "completed",
  "steps": ["read_file", "write_file", "run_tests"],
  "summary": "Função criada e testes passaram"
}

Nervos validados

  • Using tools

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para entender como ferramentas estendem o modelo com ações externas.

    Validado: A documentação oficial apresenta ferramentas como extensão de capacidades do modelo.

  • Function calling

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para modelar funções locais que o agente pode chamar com parâmetros estruturados.

    Validado: Function calling é o padrão oficial para conectar modelos a dados e ações externas.

Check de avanço

Seu agente consegue chamar uma função real, receber o resultado e continuar a resposta sem intervenção manual?

2

Fazer o agente testar e corrigir o próprio trabalho

~75 min 2 nervo(s)

Resultado prático: Criar um loop build → test → inspect error → fix → retest, com relatório de falhas em JSON.

Por que existe: A palestra destaca a virada em que o modelo passou a testar seu próprio trabalho. Isso é a diferença entre autocomplete e engenharia assistida por agente.

Tarefas práticas

  • Criar packages/validation/run_validation.ts.
  • Rodar lint, test e build em sequência.
  • Transformar falhas em relatório JSON.
  • Fazer o agente corrigir até todos os checks passarem.

Entregáveis

  "errors": [
    {
      "command": "npm run test",
      "message": "Expected 4, received 5"
    }
  ]
}

Nervos validados

  • Codex CLI

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para praticar agente local que lê, edita, executa comandos e revisa diff.

    Validado: A documentação do Codex CLI valida o uso local para trabalho de código no terminal.

  • Codex best practices

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para calibrar prompting, planejamento, validação e critérios de conclusão.

    Validado: As melhores práticas oficiais cobrem prompting, ferramentas, MCP, skills e validação.

Transformar o fluxo em uma Skill reutilizável

~60 min 2 nervo(s)

Resultado prático: Criar uma skill feature-delivery com instruções, scripts, templates e critério de parada.

Por que existe: A palestra cita customização e plugins como forma de ampliar o produto. Na prática, uma skill transforma um workflow confiável em ativo reutilizável.

Tarefas práticas

  • Criar packages/skills/feature-delivery/SKILL.md.
  • Adicionar templates de plano, review e relatório final.
  • Acoplar validate.sh à skill.
  • Testar a mesma skill em uma feature pequena.

Entregáveis

feature-delivery/SKILL.mdtemplates/plan.mdtemplates/review.mdscripts/validate.sh

Skill mínima

---
name: feature-delivery
description: Use quando precisar implementar uma feature completa com planejamento, código, testes, validação e relatório final.
---

# Feature Delivery Skill

## Fluxo obrigatório
1. Entender a intenção.
2. Mapear arquivos afetados.
3. Criar plano curto.
4. Implementar a menor alteração possível.
5. Rodar validação.
6. Corrigir falhas.
7. Gerar relatório final.

## Critério de parada
A tarefa só termina quando lint, testes e build passarem.

    Validado: A documentação oficial define skills como pacotes reutilizáveis para orientar o Codex.

  • Introducing the Codex app

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para entender por que workflows longos precisam de coordenação, estado e múltiplas tarefas.

    Validado: O anúncio do Codex app descreve uma experiência para coordenar agentes e tarefas de engenharia.

6

Reproduzir o padrão de harness e App Server

~110 min 2 nervo(s)

Resultado prático: Criar um runtime com threads, event bus e protocolo JSON-RPC/WebSocket entre UI e agente.

Por que existe: A palestra fala sobre harness aberto e servidor de aplicação como camada que permite reutilizar o mesmo loop em CLI, app, IDE e integrações. Você vai construir uma versão didática desse padrão.

Tarefas práticas

  • Criar apps/agent-runtime/server.ts.
  • Definir protocolo thread.create, thread.message e approval.resolve.
  • Criar event_bus.ts para emitir eventos estáveis.
  • Permitir trocar a UI sem trocar o runtime.

Entregáveis

agent-runtimeprotocol.tsthread_manager.tsevent_bus.tsJSON-RPC ou WebSocket

Contrato JSON-RPC simplificado

{ "method": "thread.create", "params": { "repo": "." } }
{ "method": "thread.message", "params": { "threadId": "abc", "text": "implemente X" } }
{ "method": "approval.resolve", "params": { "id": "cmd-1", "approved": true } }

Nervos validados

  • Unlocking the Codex harness

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para entender App Server, JSON-RPC, eventos, aprovações e integração com UIs.

    Validado: O artigo técnico descreve como o App Server conecta clientes ao Codex core por uma API bidirecional.

  • Unrolling the Codex agent loop

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para entender o loop central de agente, ferramentas, patches e validação.

    Validado: O artigo desmonta o loop de agente usado pelo Codex e seu harness.

Adicionar subagentes para revisão paralela

~80 min 2 nervo(s)

Resultado prático: Criar review-pr com subagentes de segurança, bugs, testes, arquitetura e manutenibilidade.

Por que existe: A palestra fala de agentes tomando várias abordagens em paralelo. Em engenharia, o primeiro uso prático disso é review especializado do mesmo diff.

Tarefas práticas

  • Extrair git diff main...HEAD.
  • Enviar o diff para cinco perfis de revisão.
  • Consolidar achados em AI Review Report.
  • Bloquear conclusão caso haja risco crítico.

Entregáveis

Nervos validados

  • Subagents

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para decompor uma tarefa em especialistas e consolidar o resultado.

    Validado: A documentação oficial descreve subagents como mecanismo de delegação especializada.

  • Agents SDK

    Fonte oficial validada · recurso técnico

    Quando seguir: Use quando a orquestração de ferramentas, estado e múltiplos agentes ficar recorrente.

    Validado: Agents SDK documenta agentes, execução, orquestração e integração de ferramentas.

8

Medir valor: custo, latência, qualidade e contexto

~90 min 4 nervo(s)

Resultado prático: Criar telemetria de execução, dashboard de custo/latência, evals e estratégia de contexto longo.

Por que existe: A palestra chama isso de maximização de valor. Não basta gastar tokens. O sistema precisa mostrar se economizou tempo, reduziu falha ou aumentou qualidade.

Tarefas práticas

  • Registrar tokens de entrada, saída e cache.
  • Registrar latência por etapa e quantidade de loops.
  • Criar evals para features com validação obrigatória.
  • Testar prompt caching e compaction em tarefas longas.

Entregáveis

  "outputTokens": 3000,
  "cachedTokens": 8000,
  "toolCalls": 9,
  "validationLoops": 3,

}

Nervos validados

  • Working with evals

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para testar qualidade do agente contra critérios objetivos.

    Validado: A documentação de evals orienta como avaliar outputs e workflows.

  • Compaction

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para tarefas longas que precisam preservar estado sem carregar todo o histórico bruto.

    Validado: Compaction reduz contexto preservando o estado necessário para continuidade.

  • Cost optimization

    Fonte oficial validada · recurso técnico

    Quando seguir: Use para transformar custo e latência em decisão técnica.

    Validado: A documentação de custo cobre redução de tokens, batch e processamento flexível.

  • Prompt caching

    Fonte oficial validada · recurso técnico

    Quando seguir: Use quando há prefixos de prompt repetidos, como AGENTS.md e instruções fixas.

    Validado: Prompt caching reaproveita prefixos elegíveis para reduzir custo e latência.

Check de avanço

Você consegue provar que uma automação economizou tempo ou melhorou qualidade, em vez de apenas consumir tokens?

Boss final: feature completa do zero ao PR validado

~180 min 3 nervo(s)

Resultado prático: Entregar uma feature real de estimativa de custo de execução de agentes, com API, UI, testes, review paralelo, telemetria e documentação.

Por que existe: A condição final é provar que você consegue conectar intenção, execução, validação, revisão e entrega. Esse é o núcleo técnico da palestra transformado em projeto.

Tarefas práticas

  • Criar POST /runs/cost-estimate.
  • Criar UI para estimar custo por tokens.
  • Adicionar testes unitários e integração.
  • Rodar validação completa.
  • Rodar subagentes de review.
  • Gerar documentação final e PR report.
