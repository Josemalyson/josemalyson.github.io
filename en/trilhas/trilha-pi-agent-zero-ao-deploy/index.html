Construa um agente como o Pi, do primeiro tipo ao deploy.

Uma trilha prática de engenharia reversa e reconstrução. A condição de parada não é quantidade de tópicos: é cobertura arquitetural. Ao final, você terá um monorepo TypeScript com API multi-provider, runtime de agente, coding harness, sessões em árvore, compactação, extensões, skills, TUI, SDK, RPC, sandbox, testes e distribuição.

Escopo temporal: o repositório inspecionado estava na linha v0.80.x em julho de 2026. O pacote orchestrator é tratado como experimental, separado do núcleo obrigatório.

Arquitetura-alvo

A dependência flui das interfaces de entrada para o harness, depois para o runtime e finalmente para a API de modelos. Persistência, recursos e UI orbitam a composição sem contaminar o provider layer.

CLI / TUI / JSON / RPC / SDKEntradas
↓
pi-coding-agentComposição, sessões, recursos
↓
pi-agent-coreLoop, estado, tools, eventos
↓
pi-aiProviders, auth, streaming
↓
Model APIsOpenAI, Anthropic, Google…

Camada paralela: pi-tui fornece primitives de terminal; orchestrator supervisiona processos RPC e permanece experimental.

Como executar a trilha

  1. Não avance apenas por leitura. Cada estação termina em artefatos e critérios verificáveis.
  2. Mantenha SPEC.md, ARCHITECTURE.md, ADRs, threat model, runbooks e changelog desde o início.
  3. Comece com provider falso. Adicione provider real somente após testes determinísticos do loop.
  4. Faça uma vertical slice headless antes da TUI. A interface deve consumir contratos já estáveis.
  5. Use o projeto Pi como referência de comparação, não como código para copiar sem compreensão.

01
Fundação e engenharia reversaFundação2–3 h

Definir o produto e a filosofia minimalista

Distinguir um agent runtime, um coding harness e uma aplicação de terminal; definir conscientemente o que ficará no núcleo e o que será extensão.

Assuntos obrigatórios

  • Pi como harness moldável, não como workflow fechado
  • Separação entre pi-ai, pi-agent-core, pi-coding-agent, pi-tui e orchestrator
  • Princípios: núcleo pequeno, contratos estáveis, capacidades plugáveis
  • Funcionalidades deliberadamente ausentes: plan mode e subagentes embutidos

Critério de avanço

  • Você explica por que o projeto separa runtime, harness e UI.
  • Cada feature futura tem uma camada proprietária definida.
  • O MVP não depende de TUI para executar um turno do agente.

Laboratórios e entregáveis

0/3
Armadilhas arquiteturais
  • Copiar a interface antes de estabilizar os contratos.
  • Acoplar o loop do agente a um provider específico.
  • Transformar extensões em condicionais dentro do núcleo.
