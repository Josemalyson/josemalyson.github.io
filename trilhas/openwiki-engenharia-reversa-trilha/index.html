Engenharia Reversa OpenWiki

Trilha técnica completa para construir um projeto do zero ao deploy

Nível avançado Engenharia reversa + implementação Zero ao deploy

OpenWiki: engenharia reversa, trilha de estudo e construção de um clone produtivo

Esta trilha foi desenhada para parar apenas quando o conjunto de estações, nervos, entregáveis e checks cobrir a construção de uma ferramenta nova inspirada no OpenWiki: CLI TypeScript, agente documental, prompt, coleta Git, persistência, segurança, automação CI e publicação.

Resultado

CLI documental instalável

Arquitetura

Ink + DeepAgents + Git

Deploy

npm + GitHub/GitLab CI

Critério final

Repo real documentado por PR

Mapa mental do OpenWiki

Usuário / CI
  -> CLI Ink ou --print
  -> Parser de comando
  -> Onboarding/env local
  -> Provider registry + modelo
  -> Git evidence + metadata anterior
  -> Prompt documental
  -> DeepAgents backend local
  -> Escrita de openwiki/
  -> Upsert em AGENTS.md/CLAUDE.md
  -> Snapshot pós-run
  -> .last-update.json se houve mudança
  -> PR/MR agendado

Ponto de parada

A trilha é considerada completa quando você consegue criar um pacote CLI novo, instalar em outro repositório, gerar a wiki inicial, atualizar por diff, não vazar segredos, rodar testes, publicar pacote e abrir PR/MR automático de atualização.

Fluxo interno do runtime
CLI command
  -> parseCommand()
  -> loadEnv()
  -> resolveProviderAndModel()
  -> collectGitEvidence()
  -> snapshotBefore()
  -> buildPrompt(command, evidence, metadata)
  -> createDeepAgent({ model, backend, checkpointer })
  -> stream events to UI/stdout
  -> snapshotAfter()
  -> write .last-update.json only if docs changed
Workflow GitHub Actions base
name: MyWiki Update
on:
  workflow_dispatch:
  schedule:
    - cron: "0 8 * * *"
permissions:
  contents: write
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { persist-credentials: true }
      - uses: actions/setup-node@v4
        with: { node-version: "22" }
      - run: npm install --global @sua-org/mywiki-agent
      - run: mywiki --update --print
        env:
          CHAVE_DO_PROVEDOR: ${{ secrets.SUA_CHAVE }}
          MYWIKI_MODEL_ID: z-ai/glm-5.2
      - uses: peter-evans/create-pull-request@v7
        with:
          add-paths: mywiki
          branch: mywiki/update
          commit-message: "docs: update MyWiki"
          title: "docs: update MyWiki"
Prompt rules essenciais
Você é um agente documental para repositórios.
Regras:
- Escopo: apenas o repositório atual.
- Não leia .env, chaves, credenciais, ~/.ssh ou arquivos fora do root.
- Use evidência do filesystem e do Git; não invente fatos.
- Escreva documentação sob /mywiki.
- Prefira páginas densas e navegáveis a stubs rasos.
- Atualize AGENTS.md/CLAUDE.md com referência curta para /mywiki/quickstart.md.
- Em update, concentre-se nas mudanças desde .last-update.json.

Definition of Done — projeto novo do zero ao deploy

  • CLI instalado globalmente e executando em Node >=20.
  • `--help`, `--init`, `--update`, `--print`, `--modelId` e `--dry-run` testados.
  • Provider registry com OpenAI, Anthropic, OpenRouter e OpenAI-compatible.
  • Credenciais gravadas fora do repo, com permissões restritivas e diagnóstico mascarado.
  • Git evidence coleta status, HEAD, commits, diff e change window por metadata.
  • Agent runtime usa backend de filesystem/shell com limites, timeout e root do repo.
  • Prompt proíbe segredos e força docs baseadas em evidência.
  • Wiki inicial tem quickstart, arquitetura, agent workflow, CLI, operações, testes e source map.
  • AGENTS.md/CLAUDE.md recebem referência idempotente para a wiki.
  • Snapshot ignora `.last-update.json` e evita metadata churn.
  • Testes cobrem parser, env, snapshot, upsert e Git evidence.
  • GitHub Actions e GitLab CI geram PR/MR somente com diffs reais.
  • Pacote npm empacotado com `files` mínimo e smoke test de instalação.
  • Documento de segurança bloqueia paths sensíveis e descreve modo sandbox/CI.
